# 代理链路与批量订阅

原有节点、账号、直连订阅和同步功能继续保留。在此基础上新增独立的代理链路，链路由管理员手动创建，与用户账号无关。订阅可以同时包含多个直连节点和多个代理链路。

例如手动创建 `中转 A → 落地 a`、`中转 A → 落地 b`、`中转 B → 落地 a`。用户甲的订阅可选择直连 a、A → a、A → b；用户乙可选择 B → a。同一链路可以分配给多个订阅，每个用户获得独立凭据。

## 接入已有节点

1. 在节点管理中录入节点及 SSH 认证信息，并选择“落地节点”或“中转节点”。已有未分类的普通节点默认作为落地，原有直连方式继续可用。节点需要 Python 3、curl、systemd，以及 root 或免交互 sudo 权限。
2. 先打开落地节点的“服务配置”齿轮图标，点击“读取现有配置”，再读取中转。此步骤用于将手工部署的配置导入平台，读取账号和实际 Reality 参数，不改写远程配置、不重启代理；只需首次接入或远程配置被手工修改后操作。
3. 在“代理链路”手动选择中转节点和已读取配置的落地节点，创建并命名链路。系统自动生成链路专用的上游传输账号，连接参数由平台维护，界面不提供单独查看、复制或编辑入口。此时不创建客户账号、不修改远程服务；同步时自动下发上游配置。已有服务中的底层用户路由会保留，系统不会据此自动生成链路。
4. 在订阅管理新增或编辑订阅，选择直连节点或已创建的代理链路。链路节点自动创建独立客户入口账号，链路内用户复用同一上游传输连接，用户权限和用量在入口分别管理；落地凭据不分发给客户端。直连仍可选择已有账号或自动创建。
5. 保存配置变更后默认自动同步：变更稳定约 5 秒后排队下发，连续操作合并处理。需要时也可使用“立即同步 / 重试同步”图标。待发布落地先更新，再更新中转；已生效的共享上游连接不会因新增链路用户而重复下发。同一中转上的全部链路共用一次配置发布，仍保留候选配置校验和失败回滚。
6. 原有未接管的直连节点沿用原来的同步流程。已接管节点的账号变更需要发布配置。

链路名称可以编辑。已分配账号的链路保留固定的中转与落地，避免修改链路时直接影响所有用户；需要改变路径时，手动创建另一链路并为订阅添加。删除链路前需要删除其客户账号；删除链路或更换未使用链路的落地时，原专用连接将在下次发布旧落地时撤销。删除节点前需要移除引用它的链路。

## 批量操作

落地节点沿用原有“账号管理 → 关联订阅”，不再额外添加重复入口。代理链路使用“关联订阅”图标，订阅页面使用“批量管理订阅”，均以与原有账号管理相同的“已关联 / 可分配”列表管理订阅。

- **确认分配**：在“可分配”列表中勾选多份已有订阅，自动创建或复用该目标所需的客户账号，批量加入直连节点或链路，保留其他节点。已有同一目标节点时自动跳过。
- **解除关联**：在“已关联”列表中勾选订阅，只移除所选目标。未被其他订阅使用的客户账号会删除；共享账号、链路的上游传输账号及其他节点会保留。权限撤销需同步配置后生效。

支持搜索、全选，每批最多 200 份。用户订阅在订阅管理中创建，关联界面不再提供批量名称编辑器。每份订阅单独提交数据库事务，账号创建、关联或解除失败时整项回滚；其他成功项继续保留。结果逐项显示，失败项保留勾选以便重试。同一批次只为每个原有直连节点触发一次后台同步。

支持现有固定服务布局：

| 类型 | systemd 服务 | 配置路径 |
| --- | --- | --- |
| 中转 | `xray-relay` | `/usr/local/etc/xray-relay/config.json` |
| 新落地 | `xray-exit` | `/usr/local/etc/xray-exit/config.json` |
| 原有 v2ray-agent 落地 | `xray` | `/etc/v2ray-agent/xray/conf/07_VLESS_vision_reality_inbounds.json`，兼容既有的替代文件名 |

第一版接管单个 VLESS Reality 入站，不能直接接管任意自定义中转路由或协议组合。已接管节点禁止使用原有“安装”接口覆盖代理服务。SSH 主机公钥在首次接管时记录，之后不匹配会拒绝连接。

## SSH 管理跳板

控制中心直连落地 SSH 超时、但中转能够连接落地时，在落地节点的新增或编辑表单中，将“SSH 管理跳板”设为已读取配置的中转节点。默认仍为直接连接。连接路径为“控制中心 → 中转 SSH → 落地 SSH”；落地使用自身的密钥或密码认证，私钥保留在控制中心，不复制到中转。跳板和落地分别校验主机公钥。

配置读取、账号导入、配置同步、监控安装和原有 SSH 安装流程均使用该路径。它只改变管理连接，不修改订阅中的节点地址，也不自动创建用户代理链路。第一版支持一级跳板，拒绝自身、循环、多级跳板和被引用跳板的删除。已有节点正在同步时不能改换跳板。经跳板的延迟检查包含 SSH 连接耗时，不代表大陆客户端的代理延迟。

现有 v2ray-agent 可能使用“公网 dokodemo-door → 本机 Reality”的结构。平台读取唯一可识别的公网入口端口，保留内部 Reality 端口和原有转发配置；也支持唯一的无 tag Reality 入站。读取时优先保留节点仍接受的既有 SNI 和 Short ID，避免不必要的订阅变化。

## 保存与同步

已接管节点的配置变更在事务提交时标记待同步，数据库中的状态同时作为任务队列。后台每秒检查一次，变更稳定约 5 秒后自动执行；批量和连续操作合并为一次节点任务。页面显示“等待自动同步 → 同步中 → 已生效”，失败图标可悬浮查看具体原因，也可手动立即同步或重试。平台重启后继续处理待同步任务；中断的发布会标记失败，要求核对实际配置，不盲目重试。

账号新增、修改、删除，订阅启停、额度修改、节点关联与解除，以及链路上游凭据新增或移除均进入该流程。同步认领与配置修改锁定同一节点记录，同步期间的相关修改会明确失败，避免覆盖或遗漏。节点名、国家旗帜、链路名和备注直接更新显示，不触发代理重启；使用稳定统计键的账号改名也不触发同步。读取配置不创建新的同步任务，已有待同步任务继续保留。

自动和手动同步使用同一条发布流程：

1. 核对远程配置哈希，发现人工修改则停止，要求重新读取核对。
2. 生成候选配置。若与已核对哈希的运行配置相同，仅更新生效记录，不替换文件或重启；有变更时使用现有 Xray 二进制校验，原有 confdir 布局校验完整目录。
3. 备份旧文件，原子替换，重启对应代理服务并检查状态。
4. 用临时本地客户端经过实际入口和落地，请求出口 IP 与完整 HTTPS 网页。每个不同落地至少验证一个启用账号。
5. 校验、重启或网页验证失败时保留或恢复旧配置。成功后在数据库事务中保存生效账号、落地绑定和配置哈希。

备份位于节点 `/var/lib/v2raydash/backups`，目录权限 0700、文件 0600。数据库收尾失败时会尝试恢复刚才的备份；SSH 中断、节点掉线或控制中心进程被终止时，无法保证自动恢复，页面会标记失败，需要重新读取节点核对实际状态。落地与中转分别发布，不构成跨节点事务。

有配置变更的发布会重启对应代理，已有连接可能短暂中断。新增链路节点需要刷新订阅；尚未发布的新增账号不会提前进入订阅。修改链路名称不改变节点、端口或账号凭据。

账号停用、删除、订阅停用和额度修改在自动同步成功后更新节点权限。第一版按发布时的额度判断是否启用账号，尚未实现实时超额自动断开和自动故障切换。

## 订阅与用量

- Clash Meta / Clash Verge 完整配置沿用现有模板，保留 13 个策略组、872 条规则，使用节点实际 Short ID。
- 上游传输账号由链路自动维护，不进入用户账号列表，不能单独修改、添加到客户订阅或导出订阅。
- 中转用量只在入口统计一次，上游传输账号及已引用的上游账号不重复计入客户用量。已有直连用户与中转不应共用一个上游账号；新增线路自动使用专用账号。
- 节点侧验证不能代替大陆客户端到中转的实测，界面明确显示验证视角。

## 监控 Agent

构建 Linux amd64 Agent，并通过 `AGENT_BINARY_PATH` 指定控制中心可以读取的文件：

```sh
cd agent
GOOS=linux GOARCH=amd64 go build -o ../v2raydash-agent-linux-amd64 ./cmd/agent
```

设置控制中心公网 HTTPS 地址，在节点“服务配置”中点击“安装 / 更新监控 Agent”。该操作只更新 `v2raydash-monitor`，不重启代理核心。它与同步配置独立；原有“安装代理与 Agent”入口则是首次安装代理核心并附带监控，已读取配置的节点使用独立监控安装，避免重装覆盖现有线路。监控以专用系统用户运行，Xray 二进制及本地 Stats API 必须对该用户可访问；Stats API 应仅监听回环地址。新落地发布会补齐 Stats API，原有落地需要已有的 Stats 配置。

每个已接管节点使用独立 PSK，控制中心只保存哈希。Agent 保留累计计数器、核心运行周期和持久化待发送队列，网络重试或 Agent 重启不会重复累计相同用量。旧的未接管节点保留原有心跳协议；接管后必须更新监控才能继续通过身份校验。第一版监控安装支持 Linux amd64。

## 本地预览与验收边界

可用 `SERVER_HOST=127.0.0.1`、独立数据库和独立端口启动控制中心；前端通过 `V2RAY_API_TARGET` 指向该端口。`VITE_PREVIEW=true` 显示示例环境提示，不应在正式构建中启用。

本地示例数据不包含线上 SSH 凭据，也不能作为实际代理使用。测试覆盖真实 PostgreSQL 流程、真实 Xray 配置校验、隔离文件系统的替换与回滚、Agent 重试队列及浏览器操作。正式接管、监控安装和发布仍需在真实节点另行验收。

## 订阅中的国家旗帜

直连节点使用自身国家旗帜；代理链路使用当前已生效的落地节点国家旗帜。同一个香港中转连接美国和日本落地时，分别显示美国和日本旗帜。待同步的路由变更不会提前改变已有线路的国家图标。Clash Meta、VLESS、Sing-box 及单账号导出使用一致的命名规则，连接地址仍为中转入口。

失败任务不会持续重试。修正配置并保存后会重新排队，也可手动重试；远程配置被人工修改导致哈希不一致时，先重新读取核对。自动任务结果写入操作日志。生产演练可通过 `NODE_AUTO_SYNC=false` 停用工作器，正式部署默认启用。
