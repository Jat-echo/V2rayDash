# 监控中心图表化设计

## 1. 概述

将监控中心从实时数值显示改为时间范围曲线图展示，并修复入站/出站带宽统计问题。

## 2. 核心变更

### 2.1 后端变更

#### 2.1.1 Agent 带宽采集
- 在 `collector.go` 的 `Collect()` 方法中添加 `getBandwidth()` 函数
- 读取 `/proc/net/dev` 获取网卡累计收发字节数
- 将 `bandwidth_in` 和 `bandwidth_out` 设置为累计值（不是差值）

#### 2.1.2 API 扩展
新增时间范围查询参数：

```
GET /api/logs/node-status?time_range=1h|4h|12h|24h&server_id=xxx
```

响应数据结构：
```json
{
  "server_id": "xxx",
  "metrics": {
    "cpu": [{ "time": "2026-05-31T23:00:00Z", "value": 25.5 }, ...],
    "memory": [{ "time": "2026-05-31T23:00:00Z", "value": 35.3 }, ...],
    "disk": [{ "time": "2026-05-31T23:00:00Z", "value": 38.0 }, ...],
    "bandwidth_in": [{ "time": "2026-05-31T23:00:00Z", "value": 1024000 }, ...],
    "bandwidth_out": [{ "time": "2026-05-31T23:00:00Z", "value": 512000 }, ...]
  },
  "current": {
    "cpu_percent": 25.5,
    "memory_percent": 35.3,
    "disk_percent": 38.0,
    "bandwidth_in": 1024000,
    "bandwidth_out": 512000,
    "v2ray_status": "running"
  }
}
```

**注意：** `bandwidth_in` 和 `bandwidth_out` 在 `metrics` 中返回的是**时间范围内的差值**（即：当前累计值 - 时间范围内最早累计值），这样前端可以直接绘制曲线而不需要再计算。

#### 2.2.3 Tab 切换实现
- 4 个时间范围 Tab: 1小时 | 4小时 | 12小时 | 24小时
- 默认选中 1小时
- 切换时重新请求数据并渲染图表

## 3. 数据流

```
Agent (每30秒)
    │
    ▼
[bandwidth_in, bandwidth_out] = 累计网卡字节数
    │
    ▼
后端存储 node_status (原始累计值)
    │
    ▼
前端请求 /api/logs/node-status?time_range=4h
    │
    ▼
后端 SQL: SELECT WHERE reported_at > NOW() - INTERVAL '4 hours'

后端计算带宽差值:
  - 获取时间范围内最早一条记录的 bandwidth_in/out 作为基准
  - 每条记录的差值 = 当前值 - 基准值
  - 返回差值数组供前端绘制曲线

前端收到处理后的数据并渲染图表
```
